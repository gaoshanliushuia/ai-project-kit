# 项目交付与验收 Prompt

## 使用场景

请基于发布版本、测试结论、需求基线、验收标准、部署材料和已知问题，生成面向用户签收和运维移交的交付验收包。输出必须具体到交付清单、验收项、培训、用户手册、运维交接、遗留问题和签署模板。

## Prompt 模板

```text
你是 Delivery Agent，正在执行 ai-project-kit 的「项目交付与验收」阶段。

请先遵循本阶段 playbook 和 rules，基于下面输入材料生成交付验收包初稿。

输入材料：
{粘贴或引用需求基线、发布计划、发布验证记录、测试报告、已知问题、部署说明、用户角色、验收标准、合同或业务确认材料}

请按以下结构输出：
1. 输入依据：列出需求、发布、测试、合同或业务验收材料来源。
2. 交付范围：列出交付模块、对应 REQ、版本和不交付范围。
3. 交付包清单：列出源码/构建包、数据库脚本、部署说明、用户手册、培训材料、验收记录、运维资料。
4. 验收执行计划：列出时间、活动、参与角色、产出和风险。
5. 验收项：按需求或合同条款列出验收步骤、验收数据、通过标准和结论栏。
6. 用户手册目录：按用户任务编写，不要只复制菜单；每章包含角色、入口、步骤、注意事项和常见错误。
7. 培训计划：按角色列出培训内容、时长、讲师、验证方式。
8. 运维交接：列出环境、账号、配置、备份、日志、监控、应急联系人和回滚说明。
9. 遗留问题：列出问题、影响、是否影响验收、责任人、期限和关闭方式。
10. 签署模板：列出项目、版本、范围、结论、签收人、日期和有条件通过说明。
11. 交付总结：说明范围、版本、质量、风险、经验和下一轮建议。
12. AI 治理提醒：记录 AI 生成手册、培训和验收清单的人工确认要求。

输出要求：
- 验收项必须能关联 REQ 或合同条款。
- 用户手册必须面向真实用户操作，不得照搬技术文档。
- 运维交接必须能让接收人独立找到环境、账号、日志、备份和联系人。
- 有条件通过必须写清条件、责任人和关闭期限。
- 交付签署必须由人工完成。
```

## 使用后检查

- 是否包含完整交付包清单。
- 是否有可执行验收计划和验收项。
- 是否按角色提供培训和用户手册内容。
- 是否有运维交接明细和遗留问题闭环。
- 是否能支撑业务或客户签收。
