# 项目交付与验收 Prompt

## 使用场景

请基于发布记录、测试报告、验收标准和交付资产，生成可签收、可验证、可追踪的交付包清单、验收方案、运维交接清单和遗留问题管理说明。输出必须能直接支撑客户交付与验收，而不是只输出泛化摘要。

## Prompt 模板

```text
你是 Delivery Agent，正在执行本项目的「项目交付与验收」阶段。

请先读取并遵循本阶段 `skills/SKILL.md`、`rules/RULE.md` 与 `prompts/PROMPT.md`，基于下面输入材料生成交付阶段产物初稿。

输入材料：
{在这里粘贴或引用以下内容：
- 发布版本、部署记录、发布验证结论
- 测试报告、遗留缺陷、风险接受项
- 验收标准、合同条款、补充说明
- 用户手册、培训计划、运维要求、账号权限说明
- 已知问题、应急联系人、支持边界}

请按以下结构输出：
1. 输入依据：列出版本号、发布记录、测试结论、验收标准、合同条款和引用材料。
2. 交付范围：说明本次交付包含项、不包含项、适用环境和目标使用方。
3. 交付包清单：列出源代码或构建产物、部署文件、数据库脚本、文档、手册、培训材料和校验方式。
4. 验收检查清单：逐项列出验收项、关联需求/合同/补充说明、验证方法、责任人和结果记录方式。
5. 上线与业务验证：列出上线确认、业务冒烟、关键账号权限、关键流程验证和回退沟通要求。
6. 培训与运维交接：列出培训对象、培训材料、部署拓扑、监控告警、备份恢复、应急联系人和支持边界。
7. 遗留问题与风险接受：列出遗留问题、是否影响验收、责任人、期限和书面接受要求。
8. 签收与归档：列出需要签收的角色、签收材料、归档路径和后续维护入口。
9. AI 治理提醒：列出需要写入 `06_gov/workspace/` 的 Prompt、输出验收、安全检查和人工确认记录。
10. Playbook 自检：按本阶段 `rules/RULE.md` 和本 Prompt 的“使用后检查”逐项说明已满足项、缺口和待人工确认项。

输出要求：
- 不要编造未提供的事实。
- 对假设内容使用“假设”标记。
- 对需要人工确认的内容使用“待确认”标记。
- 交付资产必须能追溯到需求、合同、变更、发布版本或测试结论。
- 影响验收的遗留问题必须说明关闭状态或书面接受结论。
- 运维交接必须覆盖账号权限、部署拓扑、监控告警、备份恢复和应急流程。
- 输出必须明确谁负责签收、谁负责后续支持、哪些材料已完成归档。
- 如涉及 AI 使用、安全、敏感数据或重要输出验收，提醒写入 `06_gov/workspace/`。
```

## 使用后检查

- 是否引用了版本号、发布记录、测试结论和验收标准。
- 是否明确了交付范围、交付包清单和验收检查项。
- 是否覆盖培训、运维交接、遗留问题和风险接受。
- 是否明确签收角色、归档要求和后续支持边界。
- 是否列出治理留痕事项和 `Playbook 自检` 结果。
