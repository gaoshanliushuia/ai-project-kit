# 01 项目交付与验收

## 阶段职责

把已发布版本和项目资产交付给客户或业务使用方，完成验收签署、资料移交、培训、运维交接和遗留问题管理。

交付资产包括但不限于源代码、构建产物、部署包、用户手册、操作说明、培训材料、验收记录、运维资料和交付总结。

## 关键输入

- 发布版本、源代码或构建产物、部署记录、测试报告、已知问题和风险接受记录
- 合同、验收标准、培训计划、运维要求和账号权限清单
- 上线窗口、应急预案、业务确认人和支持人员安排

## 执行动作

- 准备交付包清单、上线检查、部署确认、业务验证和应急支持。
- 组织用户培训、操作说明和运维交接。
- 按验收标准逐项验证，记录通过、失败和补充说明。
- 管理遗留问题，明确责任人、期限和是否影响验收。
- 输出交付总结和项目复盘材料。

## 关键输出

- 源代码、构建产物或交付包清单
- 上线检查清单
- 验收材料和验收记录
- 培训材料、用户手册和操作说明
- 运维交接清单
- 遗留问题清单
- 项目交付总结和复盘报告

## 可量化标准

- 交付包清单完整，且能关联到发布版本。
- 验收项必须能关联到需求或合同条款。
- 影响验收的遗留问题必须关闭或获得书面接受。
- 运维资料、账号权限和应急联系人必须完整。
- 上线后观察期问题必须有分级和响应记录。

## 交接给运营或下一轮迭代

交付阶段结束后，遗留问题、优化建议和用户反馈应进入变更管理或下一轮需求池。验收记录和运维交接资料作为后续维护依据。

## AI 协同建议

- 用 AI 根据发布、测试和合同资料生成验收清单初稿。
- 用 AI 整理用户手册、操作说明、培训材料、FAQ 和运维交接清单。
- 用 AI 汇总上线问题和复盘建议。
