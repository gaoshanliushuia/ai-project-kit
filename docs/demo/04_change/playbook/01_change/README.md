# 01 变更与配置管理

## 阶段职责

管理项目实施过程中的范围、需求、设计、代码、配置、数据和发布变更，保证变更有来源、有影响分析、有审批、有实施记录、有回溯。

## 关键输入

- 变更申请、缺陷修复、客户反馈、监管要求或内部优化建议
- 当前需求、设计、代码、测试、发布和交付基线
- 影响范围、资源约束、时间窗口和风险说明

## 执行动作

- 登记变更来源、类型、原因、紧急程度和提出人。
- 分析对范围、成本、周期、质量、数据、接口、测试和上线的影响。
- 组织评审审批，明确接受、拒绝、延期或合并处理。
- 跟踪变更实施，确保受影响阶段同步更新。
- 变更完成后复核追踪链路和实际影响。

## 关键输出

- 变更申请单
- 影响分析报告
- 变更评审和审批记录
- 变更实施计划和执行记录
- 受影响项追踪矩阵
- 变更关闭和复盘记录

## 可量化标准

- 每个变更必须有唯一编号和状态。
- 每个已批准变更必须完成影响分析。
- 紧急变更必须补齐事后评审。
- 受影响需求、设计、代码、测试和发布项必须明确。
- 变更关闭前必须确认验证结果和文档同步状态。

## 交接给其他阶段

变更管理贯穿所有阶段。任何变更都要回写到受影响阶段目录，并在本组 `workspace/` 保留统一记录；需其他阶段处理的内容同步写入统一变更记录并明确责任人与处理结果。后续阶段引用新基线时，必须引用变更编号。

## AI 协同建议

- 用 AI 从变更描述中提取影响范围候选项。
- 用 AI 生成影响分析清单和评审问题。
- 用 AI 汇总变更历史，识别频繁变更来源和流程改进点。
