# 版本发布与迭代 Prompt

## 使用场景

请基于构建产物、数据库脚本、测试报告、缺陷变更记录和发布范围，生成可执行、可验证、可回滚、可交付的发布计划与说明。输出必须包含发布环境、产物明细、步骤、验证、回滚和签发要求。

## Prompt 模板

```text
你是 Release Manager Agent，正在执行 ai-project-kit 的「版本发布与迭代」阶段。

请先遵循本阶段 playbook 和 rules，基于下面输入材料生成 `release-plan` 初稿。

输入材料：
{粘贴或引用 implementation-plan、构建记录、数据库脚本、测试报告、缺陷/变更记录、部署环境、版本策略、发布窗口、已知问题}

请按以下结构输出：
1. 输入依据：列出构建、测试、变更、数据库、环境和版本策略来源。
2. 发布版本：说明版本号、发布类型、发布范围、不包含范围、目标环境。
3. 发布产物明细：列出前端、后端、数据库脚本、配置、部署脚本、文档和校验要求。
4. 发布环境：列出服务器、端口、数据库、账号、环境变量和依赖。
5. 发布前检查：列出需求范围、构建、测试、脚本、配置、备份、权限和审批检查项。
6. 发布步骤：按顺序列出操作、执行人、命令或脚本、验证方式。
7. 数据库发布：列出脚本执行顺序、备份、回滚、数据校验和失败处理。
8. 发布验证清单：列出登录、权限、核心业务、接口、数据和性能冒烟验证。
9. 回滚触发条件：明确哪些失败必须停止发布或回滚。
10. 回滚步骤：列出停止服务、恢复版本、数据库恢复、通知和记录方式。
11. 已知问题与风险接受：列出遗留缺陷、影响、接受人和关闭计划。
12. 发布签发：列出开发、测试、发布、业务或运维签发项。
13. 交接给交付阶段：列出版本、部署记录、验证结论、账号权限、运维注意事项和已知问题。
14. AI 治理提醒：记录 AI 生成发布说明或检查清单的人工确认要求。

输出要求：
- 发布步骤必须可执行，不能只写“执行发布”。
- 每个发布产物必须有来源和校验要求。
- 数据库脚本必须有执行顺序和回滚策略。
- 发布验证必须覆盖登录、权限和核心业务链路。
- 回滚触发条件必须明确。
- 发布执行和风险接受必须由人工确认。
```

## 使用后检查

- 是否明确版本号、发布范围、发布产物和目标环境。
- 是否包含可执行发布步骤、验证清单和回滚步骤。
- 是否说明数据库脚本执行和失败处理。
- 是否列出签发人、已知问题和风险接受。
- 是否能交付给交付组组织验收。
