# 代码实现与工程管理 Prompt

## 使用场景

请基于需求基线、架构设计、软件功能说明、数据库设计和编码规则，生成代码阶段的 `implementation-plan`。该产物不是简单任务清单，而是用于指导 AI-Agent 生成可运行前后端代码、数据库脚本、测试和部署脚本的工程实施说明。

本 Prompt 主要用于生成“代码实施计划和代码生成说明”。当需要真正生成可运行代码时，应使用同目录下的 `CODE_GENERATION_PROMPT.md`，并以本 Prompt 产出的 `implementation-plan` 作为主要输入。

## Prompt 模板

```text
你是 Developer Agent，正在执行 ai-project-kit 的「代码实现与工程管理」阶段。

请先遵循本阶段 playbook、rules 和 coding standards，基于下面输入材料生成 `implementation-plan-v1.0.md` 初稿。

输入材料：
{在这里粘贴或引用以下材料：
- 需求基线，例如 01_req/workspace/01_requirements/07_baseline/
- 需求追踪矩阵，例如 01_req/workspace/01_requirements/05_traceability/
- 原型说明或可运行原型，例如 01_req/workspace/01_requirements/03_prototypes/
- 架构设计，例如 02_build/workspace/01_architecture/
- 软件功能说明文档，例如 02_build/workspace/02_design/
- 数据库设计，例如 02_build/workspace/03_database/
- 编码规则，例如 02_build/playbook/04_codebase/rules/
- 项目技术栈、部署环境、测试要求或其他约束}

请按以下结构输出：
1. 文档目标：说明本 implementation-plan 用于指导 AI-Agent 和开发人员生成哪些可运行产物。
2. 输入依据：列出需求基线、原型、架构、软件功能说明、数据库设计和编码规则的来源与使用方式。
3. 实施边界：明确本阶段必须实现、不实现、可简化项和需要人工确认的假设。
4. 推荐技术栈：说明前端、后端、数据库、本地部署和测试技术栈；如果技术栈未确认，必须标记“待确认”。
5. 目标工程结构：给出项目根目录、前端目录、后端目录、数据库脚本目录和部署脚本目录。
6. 统一数据定义：基于数据库设计和功能说明整理实体、字段、类型、必填、唯一性、枚举、状态、数据范围和业务约束。
7. 通用接口规范：定义统一响应结构、分页结构、错误码、权限上下文和鉴权处理方式。
8. 模块级开发任务：按 CODE 编号列出对应 REQ、DES、DB、前端页面、后端接口、数据约束和必须实现的业务规则。
9. 模块开发功能详述：每个 CODE 模块必须独立成章，写清功能目标、前端页面要求、后端接口要求、数据约束、业务规则、异常场景、AI 生成要求和验收标准。
10. 前端实现要求：列出页面路由、组件结构、API 封装、表单校验、角色菜单和错误展示要求。
11. 后端实现要求：列出 Controller、Service、Repository、Entity、DTO、异常处理、事务边界和权限过滤要求。
12. 数据库脚本要求：列出 schema、seed、初始化数据、索引、约束和回滚或重建说明。
13. 部署与运行脚本要求：列出 docker-compose、env.example、start/stop 脚本、本地运行命令和访问地址要求。
14. 测试与验证要求：列出单元测试、接口测试、前端验证和运行验收命令。
15. AI-Agent 生成顺序：把代码生成拆成可审查的增量步骤，不允许一次性生成不可控的大块系统。
16. AI-Agent 提示词模板：至少提供“生成项目骨架”“生成一个业务模块”“生成部署脚本”的 Prompt 示例。
17. 人工审查清单：列出开发人员必须审查的权限、安全、数据约束、可运行性、测试和部署项。
18. 本阶段输出：列出代码、脚本、测试、构建、评审、缺陷、运行说明等应放入哪些目录。
19. 交接给测试阶段：列出可测试版本、启动方式、初始化方式、测试账号、已知问题和 REQ/DES/CODE 映射。

输出要求：
- 不要编造未提供的事实。
- 对假设内容使用“假设”标记。
- 对需要人工确认的内容使用“待确认”标记。
- AI-Agent 不得直接依据访谈纪要或口头需求生成代码，必须引用已确认的需求、设计、数据库和编码规则。
- 数据定义必须包含字段类型、必填、唯一性、枚举值、状态值、范围约束和跨表业务规则。
- 开发任务必须能追踪到 REQ、DES、DB 和 CODE 编号。
- 每个 CODE 模块必须独立说明到 AI-Agent 可以按该章节生成对应前后端代码，不能只写一句任务名称。
- 前端、后端、数据库和部署脚本要求必须能支撑生成可运行系统。
- 权限、数据安全、成绩范围、重复数据、事务边界、初始化数据和部署配置必须明确写出人工审查点。
- 如涉及 AI 使用、安全、敏感数据或重要输出验收，提醒写入 `05_gov/workspace/`。
```

## 使用后检查

- 是否引用了上游输入或编号。
- 是否区分已确认、假设和待确认内容。
- 是否形成可评审、可交接、可追踪的结果。
- 是否列出需要人工确认或治理留痕的事项。
- 是否生成了足够指导 AI-Agent 产出可运行前后端代码的 `implementation-plan`。
- 是否覆盖前端、后端、数据库、测试、部署脚本和本地运行说明。
- 是否明确数据定义、数据约束、权限规则、事务边界和错误处理。
- 是否每个 CODE 模块都有独立详细章节，足够指导 AI-Agent 生成代码。
- 是否把代码生成拆成可审查的增量步骤，而不是一次性生成不可控的大块代码。
- 是否明确下一步可使用 `CODE_GENERATION_PROMPT.md` 生成可运行前后端代码、测试和部署脚本。
