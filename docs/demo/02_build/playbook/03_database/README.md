# 03 数据库设计

## 阶段职责

把业务对象、状态规则、查询需求和集成数据转化为稳定的数据模型、脚本、迁移策略和数据质量控制方案。

## 关键输入

- 需求中的数据需求、报表需求、审计要求和权限要求
- 详细设计中的领域对象、状态机、接口字段和业务规则
- 现有数据结构、历史数据、主数据规范和集成约束

## 执行动作

- 建立概念模型、逻辑模型和物理模型。
- 定义表、字段、索引、约束、字典、主外键和审计字段。
- 设计初始化数据、迁移脚本、回滚脚本和数据校验脚本。
- 评估容量、查询性能、归档、备份和恢复要求。
- 明确敏感数据、脱敏、权限和审计要求。
- 将数据对象映射到需求、接口和测试数据。

## 关键输出

- ER 图和数据模型说明
- 表结构设计和字段字典
- DDL、DML、迁移和回滚脚本
- 数据质量规则和校验清单
- 容量与索引设计说明
- 数据库评审记录

## 可量化标准

- 业务核心表字段字典完整率达到 100%。
- 每个关键查询都有索引或性能说明。
- 每个迁移脚本都有回滚或补偿策略。
- 敏感字段必须标注分类、访问控制和脱敏要求。
- 数据库变更必须能关联到需求、设计或变更单。

## 交接给下一阶段

交给开发和测试阶段的材料必须包括表结构、字段规则、字典、初始化数据、测试数据准备方式和迁移注意事项。发布阶段必须能取得脚本执行顺序和回滚说明。

## AI 协同建议

- 用 AI 从接口字段和业务对象中生成候选表结构。
- 用 AI 检查字段命名、约束、索引和审计字段遗漏。
- 用 AI 辅助生成数据校验清单和迁移风险清单。
