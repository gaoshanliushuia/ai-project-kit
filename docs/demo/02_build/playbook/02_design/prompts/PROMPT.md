# 详细设计 Prompt

## 使用场景

请基于需求基线、可运行原型、页面说明和架构设计，生成软件功能说明文档。该文档必须足够指导 AI-Agent 生成代码、测试人员生成用例、数据库人员识别数据对象，不能只写模块概述。

## Prompt 模板

```text
你是 Architect Agent / Developer Agent，正在执行 ai-project-kit 的「详细设计」阶段。

请先遵循本阶段 playbook 和 rules，基于下面输入材料生成 `software-function-spec` 初稿。

输入材料：
{粘贴或引用需求基线、需求追踪矩阵、页面原型说明、可运行原型、架构设计、权限模型、业务规则、待确认问题}

请按以下结构输出：
1. 文档目标：说明该软件功能说明如何服务代码生成、数据库设计和测试设计。
2. 输入依据：列出需求、原型、架构和版本来源。
3. 功能说明清单：按 DES 编号列出功能、关联 REQ、关联页面、关联 ARCH。
4. 通用设计规则：定义登录态、权限、分页、删除策略、错误处理、审计和 AI 代码生成分层要求。
5. 每个功能独立章节：每个 DES 必须包含功能概述、使用角色、页面入口、页面字段、按钮和交互、接口契约、请求/响应样例、数据校验、权限规则、异常场景、测试关注点、AI 代码生成注意事项。
6. 状态与规则：列出状态字段、状态流转、禁止流转、唯一性、范围约束和跨模块规则。
7. 接口总表：列出路径、方法、请求 DTO、响应 DTO、权限、错误码。
8. 数据对象输入：列出数据库阶段需要的实体、字段、关系、索引和约束线索。
9. 前端实现输入：列出路由、页面、组件、表单、表格、角色可见性和交互反馈。
10. 测试输入：列出每个功能的正向、异常、权限、边界和回归测试点。
11. 追踪矩阵：建立 REQ、ARCH、DES、DB、CODE、QA 的映射。
12. 设计评审清单：列出必须人工确认的接口、权限、业务规则和异常口径。
13. 下游交接：明确交给数据库、编码、测试阶段的具体材料。

输出要求：
- 不要编造未确认的业务规则。
- 对假设内容使用“假设”标记，对待确认内容使用“待确认”标记。
- 每个高优先级 REQ 必须有 DES 设计项。
- 每个功能章节必须具体到字段、接口、权限、异常、测试和 AI 代码生成要求。
- 接口契约必须包含路径、方法、参数、返回、错误码和权限要求。
- 数据约束必须写清唯一性、必填、枚举、状态、范围和跨表规则。
- 文档必须能直接作为 implementation-plan 和测试用例设计的输入。
```

## 使用后检查

- 是否每个功能都有独立 DES 章节。
- 是否包含页面字段、接口契约、权限规则和异常场景。
- 是否提供请求/响应样例和测试关注点。
- 是否能指导 AI-Agent 生成前后端代码而不偏离需求。
- 是否明确数据库、编码、测试的下游输入。
