# 02 详细设计

## 阶段职责

把架构方案分解为开发可执行、测试可验证、变更可影响分析的模块设计、接口设计、流程设计、状态设计和开发实现计划。

## 关键输入

- 需求编号、验收条件和核心流程
- 架构设计、模块边界、技术决策和风险假设
- 外部接口约束、数据规则和安全权限要求

## 执行动作

- 明确模块职责、输入输出、依赖关系和边界条件。
- 设计主流程、异常流程、补偿流程和并发场景。
- 定义接口契约，包括字段、类型、校验、鉴权、错误码、超时、重试和幂等。
- 设计业务状态机、状态流转条件和禁止流转规则。
- 识别可测试点，为测试阶段提供用例设计依据。
- 将设计项映射到需求编号和架构决策编号。
- 生成 `common/` 下的公共设计文件和 `modules/` 下的模块级开发实现文档，作为代码阶段生成源码的输入。

## 关键输出

- 模块设计说明
- 接口契约和错误码表
- 流程图、时序图、状态机说明
- 权限、安全和异常处理说明
- 设计追踪矩阵
- 设计评审记录
- `common/` 公共设计文件和 `modules/` 模块级开发实现文档

## 可量化标准

- 每个开发任务都能关联到设计项。
- 核心接口字段定义完整率达到 100%。
- 高风险流程必须覆盖异常、补偿和回滚路径。
- 每个状态流转都有触发条件和禁止条件。
- 设计评审问题关闭后才能进入大规模编码。

## 交接给下一阶段

交给数据库和开发阶段的材料必须包含接口契约、数据对象、状态规则、异常策略和模块级设计与实现文档。公共设计文件合并放在 `02_build/workspace/02_design/common/`，模块级实现说明放在 `02_build/workspace/02_design/modules/`；代码阶段工作区只保存源码、构建、测试、评审和运行材料。测试阶段可直接从流程、接口、状态设计和实现计划中抽取用例。

## AI 协同建议

- 用 AI 从需求和架构中生成模块清单、接口草稿和异常分支。
- 用 AI 生成合并后的公共设计文件和独立模块级实现文档。
- 用 AI 检查流程是否缺少边界场景、失败补偿和权限路径。
- 用 AI 辅助生成测试关注点，但最终由负责人确认设计可实施性。
