# 系统架构设计 Skill

## 目标

把需求基线转化为系统边界、架构方案、技术决策和质量属性设计。

## 适用角色

- `Architect Agent`

## 输入

需求基线、核心流程、非功能目标、外部系统、部署环境、技术约束。

## 输出

系统上下文、模块边界、架构决策、集成边界、非功能方案、架构风险。

## 执行步骤

- 提取架构驱动因素和质量属性优先级。
- 定义系统边界、上下游依赖、主要数据流和用户入口。
- 比较候选架构方案，记录取舍理由和放弃原因。
- 补齐安全、容量、日志、监控、容灾和运维设计。
- 形成架构风险清单和验证计划。

## 使用要求

- 先读取本阶段 `rules/RULE.md`，再生成或检查阶段产物。
- 所有结论必须能追踪到输入材料、编号、负责人或评审记录。
- AI 生成内容只作为初稿或检查建议，关键结论必须由阶段负责人确认。
- 发现可复用经验时，回写本阶段 `rules/`、`skills/` 或 `prompts/`，并在后续版本发布中说明。
