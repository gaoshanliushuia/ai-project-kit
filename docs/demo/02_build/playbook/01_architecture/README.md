# 01 系统架构设计

## 阶段职责

把需求基线转化为可实施的系统边界、架构方案、技术决策和质量属性方案。架构阶段要解决“系统如何组成、如何集成、如何满足非功能要求、风险如何控制”。

## 关键输入

- 已基线化的需求、流程、原型和验收口径
- 非功能需求，包括性能、可用性、安全、审计、扩展和运维要求
- 现有系统、外部接口、基础设施、团队能力和技术约束
- 项目周期、预算、合规要求和上线策略

## 执行动作

- 识别架构驱动因素和质量属性优先级。
- 定义系统边界、上下游系统、用户入口和主要数据流。
- 选择架构风格，并记录备选方案、取舍理由和放弃原因。
- 设计部署、集成、安全、日志、监控、容灾和容量方案。
- 识别高风险点，形成风险清单和验证方案。
- 形成架构决策记录，避免关键决策只停留在口头。

## 关键输出

- 系统上下文图、容器图、部署图和关键链路图
- 架构设计说明书
- 技术选型与架构决策记录
- 集成与接口边界说明
- 非功能能力设计
- 架构风险清单与评审记录

## 可量化标准

- 每个高优先级非功能需求都有对应架构策略。
- 每个外部系统依赖都有协议、负责人、可用性和异常处理说明。
- 每个关键技术选型至少记录一个备选方案和取舍理由。
- 架构风险必须有等级、触发条件、缓解方案和验证方式。
- 架构评审问题必须关闭或转为明确的设计输入。

## 交接给下一阶段

交给详细设计阶段的材料必须包括模块边界、接口边界、关键流程、技术约束、架构决策和风险假设。详细设计应引用架构决策编号。

## AI 协同建议

- 用 AI 汇总需求中的架构驱动因素。
- 用 AI 生成候选方案对比表和架构评审问题。
- 用 AI 检查架构是否遗漏安全、容量、容灾和运维视角。
