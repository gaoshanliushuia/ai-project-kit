# CODE-002 主页与菜单开发实现文档

## 1. 模块标识

| 项 | 内容 |
|----|------|
| 模块名称 | 主页与菜单 |
| CODE 编号 | CODE-002 |
| 关联需求 | REQ-002 |
| 关联设计 | DES-002 |
| 关联数据 | DB-001, DB-002 |
| 依赖模块 | CODE-001 |

## 2. 功能目标

展示当前用户、角色菜单和基础统计信息，作为业务人员进入各模块的统一入口。

## 3. 前端实现要求

页面：`HomeView`

路由：`/`

页面元素：

| 元素 | 要求 |
|------|------|
| 当前用户信息 | 展示姓名、角色名称和退出入口 |
| 菜单列表 | 只展示当前角色授权的功能 |
| 统计卡片 | 展示学生数、班级数、教师数、待录成绩数 |
| 业务入口 | 菜单点击后进入对应路由 |

建议文件：

- `frontend/src/views/HomeView.vue`
- `frontend/src/layouts/MainLayout.vue`
- `frontend/src/api/dashboardApi.js`

## 4. 后端接口要求

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/auth/profile` | GET | 返回用户、角色和菜单 |
| `/api/dashboard/summary` | GET | 返回统计卡片数据 |

建议后端文件：

- `DashboardController`
- `DashboardService`
- `DashboardSummaryResponse`

## 5. 数据和统计口径

- 学生数：`student.status = active` 的数量。
- 班级数：`class_info.status = active` 的数量。
- 教师数：`teacher.status = active` 的数量。
- 待录成绩数：Demo 可用学生课程关系数减已录成绩数简化计算。

菜单数据结构建议包含：

| 字段 | 说明 |
|------|------|
| `key` | 菜单唯一标识 |
| `label` | 菜单展示名称 |
| `path` | 前端路由 |
| `reqCode` | 关联需求编号 |

## 6. 权限规则

- 所有登录用户可访问主页。
- 菜单显示由后端返回，前端只负责渲染。
- 用户手工访问未授权路由时，前端应提示无权限；后端接口仍必须拒绝未授权访问。
- 教务管理员可看到所有业务菜单。
- 班主任不能看到班级管理、教师管理维护入口。
- 任课教师不能看到学生新增或班级维护入口。

## 7. 异常和错误码

| 场景 | 错误码 |
|------|--------|
| 未登录访问主页接口 | `UNAUTHORIZED` |
| 访问未授权菜单对应接口 | `FORBIDDEN` |
| 统计查询失败 | `BUSINESS_RULE_FAILED` 或统一系统错误 |

## 8. 测试与验证

- 教务管理员能看到所有菜单。
- 班主任只看到学生查询和成绩查询相关入口。
- 任课教师只看到学生课程和成绩录入相关入口。
- 统计卡片能正常返回数字，空数据时返回 0。
- 未登录访问 `/api/dashboard/summary` 被拒绝。

## 9. AI-Agent 生成要求

- 先读取 `global-implementation-requirements-v1.0.md` 和 CODE-001 登录模块文档。
- 前端菜单必须来自当前用户接口，不应在页面中硬编码全部角色逻辑。
- `DashboardService` 可以使用简化查询，但统计口径必须在代码或 README 中说明。

## 10. 人工审查点

- 菜单是否与角色权限一致。
- 未授权路由是否前后端都有限制。
- 待录成绩数的 Demo 简化口径是否清楚。
- 首页是否能作为后续模块入口。
