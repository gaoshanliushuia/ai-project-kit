## 2. 功能目标

支持任课教师录入和编辑自己任教课程的学生成绩，支持教务管理员、班主任和任课教师按权限查询成绩。

## 3. 前端实现要求

页面：`ScoreView`

路由：`/scores`

| 区域 | 要求 |
|------|------|
| 查询条件 | 学期、班级、学生、课程、任课教师 |
| 列表字段 | 学期、学生、班级、课程、成绩、录入教师、备注 |
| 表单字段 | 学生课程关系、成绩、备注 |
| 按钮权限 | 任课教师显示录入和编辑按钮；班主任只读；教务管理员可查询全部 |
| 成绩输入 | 必须限制为数字，并在前端提示 0-100 |

建议文件：

- `frontend/src/views/ScoreView.vue`
- `frontend/src/api/scoreApi.js`

## 4. 后端接口要求

| 接口 | 方法 | 说明 |

| `/api/scores/{id}` | PUT | 编辑成绩 |

建议后端文件：

## 5. 数据约束

| 字段 | 约束 |
|------|------|
| `term` | 必填 |
| `studentId` | 必须能匹配有效学生课程关系 |
| `courseId` | 必须能匹配有效学生课程关系 |
| `teacherId` | 必须为该课程任课教师 |
| `score` | 必填整数，范围 0-100 |
| `remark` | 可为空，最大 255 字符 |

同一 `term + studentId + courseId` 只能存在一条成绩记录。

## 6. 权限和业务规则

- 教务管理员可查询全部成绩。
- 班主任只能查询本班学生成绩。
- 任课教师只能查询和维护自己任教课程的成绩。
- 任课教师不能给非任教课程录入或编辑成绩。
- 录入成绩前必须校验学生课程关系存在。
- 成绩范围校验必须在后端实现，前端校验只用于体验。

## 7. 业务流程

```text
任课教师选择学期、学生、课程
  -> 后端校验学生课程关系存在
  -> 后端校验当前教师任教该课程
  -> 后端校验成绩范围和唯一性
  -> 保存成绩
  -> 返回成绩记录
```

## 8. 异常和错误码

| 场景 | 错误码 |
|------|--------|
| 成绩为空或超出范围 | `VALIDATION_ERROR` |
| 学生未绑定该课程 | `BUSINESS_RULE_FAILED` |
| 教师无任课权限 | `FORBIDDEN` |
| 成绩重复录入 | `DUPLICATE_DATA` |
| 成绩记录不存在 | `NOT_FOUND` |

## 9. 测试与验证

- 0 和 100 可以保存。
- -1 和 101 不能保存。
- 任课教师不能录入非任教课程成绩。
- 任课教师不能编辑非授权成绩。
- 班主任只能看到本班成绩。
- 教务管理员可以查询全部成绩。
- 重复录入同一学生同一学期同一课程成绩失败。

## 10. AI-Agent 生成要求

- 先读取 `global-implementation-requirements-v1.0.md`。
- Service 层必须复用学生课程关系和教师任课关系校验。
- 前端 `ScoreView` 必须支持按角色控制按钮可见性。
- 必须生成覆盖 `0`、`100`、`-1`、`101` 的测试。
- 后端必须独立完成权限过滤，不能只依赖前端按钮隐藏。

## 11. 人工审查点

- 成绩范围约束是否在前端、后端和数据库层保持一致。
- 任课教师越权录入是否被后端拒绝。
- 班主任查询过滤是否不能被请求参数绕过。
- 成绩唯一性是否无法并发绕过。
- 编辑成绩是否复用录入时的权限和范围校验。
