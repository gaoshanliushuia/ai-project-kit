# 安全日志与可观测性要求

## 1. 通用要求主题

主题：基础安全、日志记录、错误处理和运行可观测性。

适用范围：所有后端接口、前端 API 调用、配置文件、部署脚本、测试和运行说明。

## 2. 约束目标

保证 Demo 虽然可以简化认证和部署，但不能形成明显的不安全示例。AI-Agent 生成代码时，必须保留安全边界、错误处理和基础日志，方便人工审查和后续扩展。

## 3. 具体规则

### 3.1 认证与权限

- 所有业务接口必须校验登录态。
- 所有写操作必须校验角色权限。
- 后端必须独立完成权限判断，前端按钮隐藏不能作为安全控制。
- Demo Token 或 Session 实现必须标注为简化方案，并预留替换正式认证的位置。

### 3.2 配置和敏感信息

- 不得硬编码真实密码、Token、密钥或生产地址。
- 数据库连接、端口、账号等配置必须进入 `env.example` 或配置文件。
- 示例密码只能用于 Demo，并应在 README 中说明不可用于生产。

### 3.3 日志和错误

- 登录失败、权限拒绝、关键写操作失败应有后端日志。
- 日志不得记录明文密码、Token、身份证号等敏感信息。
- API 返回错误必须使用统一错误码和用户可理解的错误消息。
- 前端不得展示数据库异常、堆栈或内部类名。

### 3.4 可观测性

- 启动脚本应输出后端地址、前端地址和数据库连接提示。
- 后端启动时应输出关键配置摘要，但不能输出敏感值。
- 测试失败时应能通过日志或错误响应定位到模块和接口。
- README 应说明如何启动、如何测试、如何验证核心业务。

## 4. 禁止事项

- 不得只在前端实现权限控制。
- 不得把 `.env`、真实凭据、私钥或生产连接串写入仓库。
- 不得吞掉异常后返回成功。
- 不得在日志中输出密码、Token 或完整请求体中的敏感字段。

## 5. 验证方式

- 人工调用未登录业务接口，确认返回 `UNAUTHORIZED`。
- 人工调用越权写操作，确认返回 `FORBIDDEN`。
- 搜索代码和配置，确认没有真实密钥或生产地址。
- 检查登录失败、权限拒绝和关键写操作失败是否有后端日志。
- 运行测试和启动脚本，确认失败时有可定位的错误信息。

## 6. 与功能模块的关系

所有 `modules/` 下的后端接口、前端 API 调用和部署说明都必须遵循本文件。模块文档只补充该模块特有的权限规则和异常场景，不重复定义通用安全和日志规则。
