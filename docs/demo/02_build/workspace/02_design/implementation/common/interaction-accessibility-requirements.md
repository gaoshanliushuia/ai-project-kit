# 交互体验与可访问性要求

## 1. 通用要求主题

主题：页面交互、用户反馈、键盘可用性和基础可访问性。

适用范围：所有前端页面、表单、按钮、弹窗、菜单、错误提示和列表操作。

## 2. 约束目标

保证 Demo 的交互行为可预测、可验证，并让不同角色用户在常见操作中获得清晰反馈。AI-Agent 生成页面时，不得只生成静态界面，必须补齐基础交互状态。

## 3. 具体规则

### 3.1 表单交互

- 提交按钮在请求进行中必须禁用或显示加载状态。
- 表单提交失败时，应保留用户已输入内容。
- 取消或关闭弹窗时，不应误提交数据。
- 关键写操作成功后应刷新列表或详情，并给出成功提示。

### 3.2 错误和确认

- 后端返回 `VALIDATION_ERROR` 时，前端应显示可理解的字段或业务提示。
- 停用学生、班级、教师、课程关系等风险操作必须二次确认。
- 越权或未登录时，应提示无权限或跳转登录，不显示空白页。

### 3.3 键盘和焦点

- 登录页初始焦点建议放在账号输入框。
- 弹窗打开后焦点应进入弹窗区域。
- 弹窗关闭后焦点应回到触发按钮或合理位置。
- 常用按钮和输入框应支持键盘 Tab 顺序访问。

### 3.4 可访问性基础

- 表单字段必须有可见 label。
- 图标按钮必须有文字说明、标题或可访问名称。
- 状态和错误提示必须有文本，不得只依赖颜色。
- 表格空状态、加载状态和错误状态必须有明确文案。

## 4. 禁止事项

- 不得提交时无加载状态，导致用户重复点击。
- 不得用浏览器默认 `alert` 作为全部交互反馈。
- 不得隐藏错误原因，只显示“系统异常”。
- 不得生成只能鼠标操作、键盘无法访问的主要流程。

## 5. 验证方式

- 人工执行新增、编辑、停用、查询流程，确认每一步都有反馈。
- 使用键盘 Tab 访问登录页、查询表单和弹窗。
- 模拟后端校验失败、未登录和无权限返回，检查页面提示。
- 检查所有表单字段是否有 label，所有图标操作是否有文字说明。

## 6. 与功能模块的关系

所有业务模块的页面、表单和弹窗必须遵循本文件。模块文档只补充该模块特有的操作流程和业务提示，不重复定义通用交互规则。
