# 全局界面风格要求

## 1. 通用要求主题

主题：界面风格、视觉层级和前端布局一致性。

适用范围：所有前端页面、布局、表单、表格、弹窗、按钮、提示信息和 README 中的界面说明。

## 2. 约束目标

让中学教务管理系统 Demo 保持统一、清晰、可审查的后台管理界面风格。AI-Agent 生成任何功能页面时，必须先遵循本文件，再读取对应模块级开发实现文档。

## 3. 具体规则

### 3.1 页面布局

- 使用后台管理常见布局：顶部用户区 + 左侧或顶部菜单 + 主内容区。
- 主内容区按“查询区、操作区、列表区、分页区、表单弹窗或详情区”组织。
- 页面标题必须与菜单名称一致，例如“学生管理”“班级管理”“成绩管理”。
- 查询区默认放在列表上方，主要按钮放在查询区下方或列表右上方。

### 3.2 颜色和视觉层级

- 主色建议使用稳定的蓝色系，用于主按钮、当前菜单和重要链接。
- 危险操作使用红色系，例如停用、删除类按钮。
- 成功、警告、错误提示必须有不同颜色或图标区分。
- 不要在同一页面引入过多强调色，Demo 中最多保留主色、危险色、成功色、警告色四类。

### 3.3 表格和表单

- 列表表头命名必须与软件功能说明中的字段语义一致。
- 状态字段使用文本加视觉标识，例如 `active` 显示“启用”，`disabled` 显示“停用”。
- 表单字段顺序应与用户录入习惯一致：基础标识、名称、关联对象、状态或备注。
- 必填字段必须有明显标识，提交失败时在字段附近或表单顶部展示错误信息。

### 3.4 空状态和加载状态

- 列表无数据时显示空状态文案，例如“暂无学生数据”。
- 接口请求过程中显示加载状态，避免用户重复点击。
- 操作成功后应给出轻量提示，并刷新相关列表或详情。

## 4. 禁止事项

- 不得在不同模块使用完全不同的页面布局。
- 不得只用颜色表达状态，必须同时提供文字。
- 不得把后端错误原样显示为数据库异常或堆栈信息。
- 不得在页面中硬编码未授权菜单或操作按钮。

## 5. 验证方式

- 人工检查所有页面是否遵循统一布局。
- 人工检查按钮颜色、状态展示和错误提示是否一致。
- 前端运行后分别访问登录、主页、学生管理和成绩管理页面，确认视觉层级清晰。
- 检查表单必填、加载、成功、失败、空状态是否都有明确反馈。

## 6. 与功能模块的关系

所有 `modules/` 下的功能模块都必须引用本文件。模块文件只描述该模块特有的页面字段、按钮和业务规则，不重复定义全局风格。
