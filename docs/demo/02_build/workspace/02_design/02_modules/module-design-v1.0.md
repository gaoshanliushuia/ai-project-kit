## 4. 模块边界

### 4.1 认证与权限边界

- 认证模块负责生成和解析当前用户上下文。
- 业务模块不得自行构造角色和数据范围，只能读取统一权限上下文。
- 前端菜单显示由后端返回，前端只做渲染和交互控制。

### 4.2 基础资料边界

- 学生管理依赖班级状态，不负责维护班级。
- 班级管理依赖教师状态，不负责维护教师任课关系。
- 教师管理负责教师资料和任课关系，供学生课程和成绩模块复用。

### 4.3 业务链路边界

- 学生课程管理负责建立成绩录入前置关系。
- 学生成绩管理必须基于学生课程关系录入成绩，不直接绕过课程关系。
- 停用学生、课程、教师或课程关系后，不删除历史成绩。

## 5. 依赖关系

```text
认证与当前用户
  -> 主页与菜单
  -> 学生管理
  -> 班级管理
  -> 教师管理
教师管理 + 学生管理
  -> 学生课程管理
学生课程管理 + 教师管理
  -> 学生成绩管理
```

## 6. 设计规则

- 每个模块必须能追踪到 REQ 和 DES 编号。
- 每个模块必须明确输入、输出、权限和异常。
- 跨模块调用优先通过 Service 方法或清晰的数据查询能力实现。
- 模块实现计划必须从本文和接口契约继续细化，不得直接从需求访谈生成。
