## 4. 通用设计规则

- 所有接口必须校验登录态。
- 所有写操作必须校验角色权限。
- 列表查询默认分页。
- 删除类操作在 Demo 中采用停用状态，不做物理删除。
- 返回错误信息应对用户友好，不暴露数据库异常。
- AI-Agent 生成代码时必须保留人工可审查的分层结构：Controller、Service、Repository、DTO、Entity。

## 5. DES-001 登录功能说明

### 5.1 功能概述

用户输入账号和密码登录系统，登录成功后进入主页。登录失败时提示账号或密码错误。

### 5.2 页面字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| username | 文本 | 是 | 登录账号 |
| password | 密码 | 是 | 登录密码 |

### 5.3 接口契约

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/auth/login` | POST | 用户登录 |
| `/api/auth/logout` | POST | 用户退出 |
| `/api/auth/profile` | GET | 获取当前用户和菜单 |

### 5.4 校验与异常

- 账号或密码为空时返回参数校验错误。
- 账号不存在或密码错误时返回登录失败。
- 停用账号不能登录。

### 5.5 AI 代码生成注意事项

- 生成 `AuthController`、`AuthService`、`LoginRequest`、`LoginResponse`。
- 登录成功响应中包含用户 ID、姓名、角色和菜单列表。
- 密码处理在 Demo 中可简化，但代码结构应预留加密校验位置。

## 6. DES-002 主页功能说明

### 6.1 功能概述

主页展示当前登录用户、角色菜单和基础数据概览。它用于验证不同角色可见菜单不同，也为业务用户提供常用入口。

### 6.2 使用角色

全部已登录用户。

### 6.3 页面元素

| 元素 | 说明 | 数据来源 |
|------|------|----------|
| 当前用户信息 | 姓名、角色 | `/api/auth/profile` |
| 菜单列表 | 按角色过滤后的菜单 | `/api/auth/profile` |
| 数据统计卡片 | 学生数、班级数、教师数、待录成绩数 | `/api/dashboard/summary` |

### 6.4 接口契约

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/dashboard/summary` | GET | 获取主页统计摘要 |

### 6.5 权限规则

- 未登录用户不能访问主页。
- 教务管理员可看到全部业务菜单。
- 班主任只能看到学生查询和成绩查询相关入口。
- 任课教师只能看到学生课程和成绩录入相关入口。

### 6.6 AI 代码生成注意事项

- 生成 `DashboardController` 和 `DashboardService`。
- 统计数据可从数据库实时查询，也可在 Demo 中使用简化查询。
- 前端菜单必须来自当前用户接口，不应在页面中硬编码全部角色逻辑。

## 7. DES-003 学生管理功能说明

### 7.1 功能概述

教务管理员可以维护学生基础信息，班主任可以查看本班学生信息。

### 7.2 使用角色

| 角色 | 权限 |
|------|------|
| 教务管理员 | 新增、编辑、查询、停用全部学生 |
| 班主任 | 查询本班学生 |

### 7.3 页面字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| studentNo | 文本 | 是 | 学号，全校唯一 |
| name | 文本 | 是 | 学生姓名 |
| gender | 枚举 | 是 | male / female |
| classId | 下拉 | 是 | 关联班级 |
| enrollmentYear | 数字 | 是 | 入学年份 |
| status | 枚举 | 是 | active / disabled |

### 7.4 操作规则

| 操作 | 角色 | 规则 |
|------|------|------|
| 新增学生 | 教务管理员 | 学号不能重复，班级必须有效 |
| 编辑学生 | 教务管理员 | 停用学生不可修改班级 |
| 查询学生 | 教务管理员、班主任 | 班主任只能查看本班学生 |
| 停用学生 | 教务管理员 | 停用后不可再分配课程 |

### 7.5 接口契约

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/students` | GET | 分页查询学生 |
| `/api/students` | POST | 新增学生 |
| `/api/students/{id}` | GET | 查看学生详情 |
| `/api/students/{id}` | PUT | 编辑学生 |
| `/api/students/{id}/disable` | POST | 停用学生 |

### 7.6 测试关注点

- 学号重复校验。
- 班级无效时不能保存。
- 班主任不能查看其他班学生。
- 停用学生不能进入课程分配。

### 7.7 AI 代码生成注意事项

- 生成 `StudentController`、`StudentService`、`StudentRepository`、`StudentEntity`。
- DTO 字段必须与页面字段保持一致。
- Service 层实现学号唯一、班级有效、权限过滤和停用规则。

## 8. DES-004 班级管理功能说明

### 8.1 功能概述

教务管理员维护年级、班级、班主任和班级状态。学生必须归属一个启用状态的班级。

### 8.2 页面字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| gradeName | 文本 | 是 | 年级，例如七年级 |
| className | 文本 | 是 | 班级，例如七年级一班 |
| headTeacherId | 下拉 | 否 | 班主任，必须引用有效教师 |
| status | 枚举 | 是 | active / disabled |

### 8.3 操作规则

| 操作 | 角色 | 规则 |
|------|------|------|
| 新增班级 | 教务管理员 | 同一年级下班级名称不能重复 |
| 编辑班级 | 教务管理员 | 班主任必须为启用教师 |
| 停用班级 | 教务管理员 | 班级下存在 active 学生时需提示风险 |

### 8.4 接口契约

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/classes` | GET | 分页查询班级 |
| `/api/classes` | POST | 新增班级 |
| `/api/classes/{id}` | PUT | 编辑班级 |
| `/api/classes/{id}/disable` | POST | 停用班级 |

### 8.5 AI 代码生成注意事项

- 生成 `ClassInfoController`、`ClassInfoService`、`ClassInfoRepository`、`ClassInfoEntity`。
- Service 层实现年级内班级名称唯一校验。
- 停用班级前检查是否存在 active 学生。

## 9. DES-005 教师管理功能说明

### 9.1 功能概述

教务管理员维护教师基础信息，并维护教师与课程之间的任课关系。

### 9.2 页面字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| teacherNo | 文本 | 是 | 教师工号，全校唯一 |
| name | 文本 | 是 | 教师姓名 |
| gender | 枚举 | 否 | male / female |
| courseIds | 多选 | 否 | 任课课程 |
| status | 枚举 | 是 | active / disabled |

### 9.3 操作规则

| 操作 | 角色 | 规则 |
|------|------|------|
| 新增教师 | 教务管理员 | 教师工号不能重复 |
| 维护任课关系 | 教务管理员 | 只能绑定 active 课程 |
| 停用教师 | 教务管理员 | 停用后不能继续作为新课程关系任课教师 |

### 9.4 接口契约

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/teachers` | GET | 分页查询教师 |
| `/api/teachers` | POST | 新增教师 |
| `/api/teachers/{id}` | PUT | 编辑教师 |
| `/api/teachers/{id}/courses` | PUT | 维护任课课程 |
| `/api/teachers/{id}/disable` | POST | 停用教师 |

### 9.5 AI 代码生成注意事项

- 生成 `TeacherController`、`TeacherService`、`TeacherRepository`、`TeacherEntity`。
- 若使用教师课程关系表，应在数据库设计中补充 `teacher_course`。
- 任课教师权限过滤应引用教师课程关系。

## 10. DES-006 学生课程管理功能说明

### 10.1 功能概述

维护学生与课程之间的关系，确保同一学生在同一学期不能重复绑定同一课程。

### 10.2 页面字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| term | 文本 | 是 | 学期，例如 2026-S1 |
| studentId | 下拉 | 是 | 学生 |
| courseId | 下拉 | 是 | 课程 |
| teacherId | 下拉 | 是 | 任课教师 |
| status | 枚举 | 是 | active / disabled |

### 10.3 接口契约

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/student-courses` | GET | 查询学生课程关系 |
| `/api/student-courses` | POST | 新增课程关系 |
| `/api/student-courses/{id}/disable` | POST | 停用课程关系 |

### 10.4 业务规则

- 学生状态必须为 active。
- 教师必须具备该课程任课关系。
- 同一 term + studentId + courseId 只能存在一条 active 记录。

### 10.5 AI 代码生成注意事项

- 数据库层需要唯一约束或服务层重复校验。
- 创建课程关系前要检查学生、课程、教师是否有效。
- 停用关系后，不影响历史成绩查询。

## 11. DES-007 学生成绩管理功能说明

### 11.1 功能概述

任课教师录入自己任教课程的学生成绩，教务管理员和班主任可按权限查询成绩。

### 11.2 页面字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| term | 文本 | 是 | 学期 |
| studentId | 下拉 | 是 | 学生 |
| courseId | 下拉 | 是 | 课程 |
| score | 数字 | 是 | 成绩，范围 0-100 |
| remark | 文本 | 否 | 备注 |

### 11.3 操作规则

| 操作 | 角色 | 规则 |
|------|------|------|
| 录入成绩 | 任课教师 | 只能录入自己任教课程 |
| 编辑成绩 | 任课教师 | 只能编辑自己录入或授权范围内成绩 |
| 查询成绩 | 教务管理员 | 查询全部 |
| 查询成绩 | 班主任 | 查询本班 |
| 查询成绩 | 任课教师 | 查询任教课程 |

### 11.4 接口契约

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/scores` | GET | 查询成绩 |
| `/api/scores` | POST | 录入成绩 |
| `/api/scores/{id}` | PUT | 编辑成绩 |

### 11.5 校验与异常

- score 必须在 0-100。
- 未绑定课程关系的学生不能录入成绩。
- 任课教师不能给非任教课程录入成绩。

### 11.6 AI 代码生成注意事项

- 生成 `ScoreController`、`ScoreService`、`ScoreRepository`、`ScoreEntity`。
- Service 层必须实现成绩范围校验和角色数据过滤。
- 测试应覆盖 0、100、-1、101 四类边界值。

## 12. 接口请求与响应样例

### 12.1 新增学生请求

```json
{
  "studentNo": "S2026001",
  "name": "陈一",
  "gender": "female",
  "classId": 1,
  "enrollmentYear": 2026
}
```

成功响应：

```json
{
  "success": true,
  "code": "OK",
  "message": "success",
  "data": {
    "id": 1001,
    "studentNo": "S2026001",
    "name": "陈一",
    "status": "active"
  }
}
```

### 12.2 成绩录入失败响应

```json
{
  "success": false,
  "code": "VALIDATION_ERROR",
  "message": "成绩必须在 0-100 之间",
  "data": null
}
```
