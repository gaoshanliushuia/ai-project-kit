# 04 代码实现与工程管理工作区

本目录用于保存代码阶段的任务拆分、构建记录、测试记录、代码评审和工程管理材料。模板默认只创建到本目录；下级目录请按需创建。

## 建议子目录

- `01_tasks/`：开发任务清单、任务与需求/设计映射、进度和责任人。
- `02_builds/`：本地构建、流水线记录、构建产物索引和失败处理记录。
- `03_tests/`：单元测试、集成测试、静态检查、依赖检查和验证证据。
- `04_reviews/`：代码评审记录、问题清单、修复记录和复审结论。
- `05_defects/`：缺陷修复记录、技术债、临时方案和遗留风险。
- `06_runtime/`：配置说明、环境变量、运行说明、部署依赖和排障 notes。

## 使用建议

- 开发任务应能追踪到需求或设计项。
- 关键路径代码应有测试或人工验证证据。
- 临时方案必须记录失效条件和后续处理计划。

## Demo 样例

本 Demo 已补充 `implementation-plan-v1.0.md`，作为代码阶段的核心实施说明。它承接需求基线、架构设计、软件功能说明和数据库设计，用于指导 AI-Agent 生成可运行的前后端代码、数据库脚本、测试和本地部署脚本。

使用时应重点关注：

- 前后端目标工程结构。
- 统一数据定义、字段约束和业务校验。
- 模块级开发任务与 REQ/DES/DB 映射。
- 前端页面、后端分层、数据库脚本和部署脚本要求。
- AI-Agent 分步生成顺序和人工审查清单。

同时，本目录补充了 `runnable-example/`，用于展示 AI-Agent 按 `implementation-plan-v1.0.md` 生成可运行代码时应交付的最小工程形态。该示例包含后端 API、前端页面、数据库脚本、部署脚本和测试。

运行方式：

```bash
cd docs/demo/02_build/workspace/04_codebase/runnable-example
npm start
```

测试方式：

```bash
npm test
```
