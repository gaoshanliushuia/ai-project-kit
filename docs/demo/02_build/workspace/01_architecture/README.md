# 01 系统架构设计工作区

本目录用于保存架构阶段的项目材料，包括需求引用、架构方案、技术决策、风险验证和评审记录。模板默认只创建到本目录；下级目录请按需创建。

## 建议子目录

- `01_inputs/`：需求基线引用、非功能需求、约束条件、现有系统资料。
- `02_context/`：系统边界、上下游系统、用户入口、关键数据流。
- `03_solution/`：架构方案、部署方案、集成方案、安全和运维方案。
- `04_decisions/`：架构决策记录、备选方案、取舍理由和放弃原因。
- `05_risks/`：架构风险、验证计划、风险关闭记录和遗留假设。
- `06_reviews/`：架构评审材料、问题清单、关闭记录和确认结论。

## 使用建议

- 每个关键架构决策应能追溯到需求、质量属性或外部约束。
- 高风险点应有验证方式，不能只停留在方案描述。
- 交接给详细设计时，应明确模块边界、接口边界和技术约束。
