## 2. 架构目标

- 支撑教务管理员、班主任、任课教师和系统管理员按权限使用系统。
- 保持 Demo 架构简单，便于演示从需求到交付的完整链路。
- 让详细设计和编码阶段可以明确识别模块边界、权限边界和数据边界。

## 3. 架构决策

| 编号 | 决策 | 理由 | 影响 |
|------|------|------|------|
| ARCH-001 | 前后端分离 | 便于展示页面原型、接口契约和代码生成链路 | 详细设计需输出页面字段和 API 契约 |
| ARCH-002 | 单体应用优先 | Demo 范围有限，模块边界清楚，不需要微服务复杂度 | 编码阶段按模块分包 |
| ARCH-003 | RBAC 权限模型 | 不同角色菜单和数据范围不同 | 详细设计需输出权限矩阵 |
| ARCH-004 | 关系型数据库 | 学生、班级、教师、课程、成绩关系明确 | 数据库阶段输出 ER 图、DDL 和字段字典 |
| ARCH-005 | REST API | 与前端页面和 AI 代码生成契约匹配 | 详细设计需输出接口路径、参数和返回值 |

## 4. 模块划分

| 模块 | 关联需求 | 后端职责 | 前端职责 |
|------|----------|----------|----------|
| 用户登录与权限 | REQ-001, REQ-002 | 登录认证、角色菜单、权限校验 | 登录页、主页菜单展示 |
| 学生管理 | REQ-003 | 学生信息 CRUD、状态控制 | 学生列表、学生表单 |
| 班级管理 | REQ-004 | 年级班级维护、班主任绑定 | 班级列表、班级表单 |
| 教师管理 | REQ-005 | 教师信息维护、任课关系维护 | 教师列表、教师表单 |
| 学生课程管理 | REQ-006 | 学生课程关系维护、重复校验 | 课程分配页面 |
| 学生成绩管理 | REQ-007 | 成绩录入、查询、权限过滤 | 成绩录入和查询页面 |

## 5. 数据流概览

```text
用户登录
  -> 后端认证
  -> 返回用户角色和菜单
  -> 前端按角色展示模块
  -> 用户访问业务页面
  -> 后端按角色过滤数据
  -> 数据库读写学生、班级、教师、课程、成绩数据
```

## 6. 风险清单

| 编号 | 风险 | 影响 | 缓解措施 |
|------|------|------|----------|
| RISK-001 | 权限边界不清 | 班主任或教师看到不该看的数据 | 详细设计输出权限矩阵，测试覆盖越权场景 |
| RISK-002 | 学生和课程关系重复 | 成绩数据重复或统计错误 | 数据库唯一约束，接口重复校验 |
| RISK-003 | 成绩边界校验缺失 | 出现 120 分等非法成绩 | 详细设计和测试明确 0-100 校验 |
| RISK-004 | Demo 范围膨胀 | 无法展示完整流程 | 排课、在线选课、家长端明确范围外 |

## 9. 运行时架构

Demo 运行时按三层组织：

```text
浏览器
  -> Vue 前端应用
  -> REST API 后端服务
  -> 关系型数据库
```

| 层 | 职责 | 示例技术 | 关键约束 |
|----|------|----------|----------|
| 前端 | 页面展示、表单校验、角色菜单展示 | Vue 3 + Vite | 不承载最终权限判断 |
| 后端 | 认证、鉴权、业务规则、事务和数据访问 | Spring Boot 或 Node.js Express | 必须重复校验所有业务规则 |
| 数据库 | 持久化学生、班级、教师、课程、成绩数据 | PostgreSQL / MySQL | 必须有唯一约束、非空约束和必要索引 |

## 10. 接口边界

| API 分组 | 路径前缀 | 主要职责 | 关联模块 |
|----------|----------|----------|----------|
| Auth API | `/api/auth` | 登录、退出、当前用户和菜单 | 用户登录与权限 |
| Student API | `/api/students` | 学生查询、新增、编辑、停用 | 学生管理 |
| Class API | `/api/classes` | 班级查询、新增、编辑、班主任绑定 | 班级管理 |
| Teacher API | `/api/teachers` | 教师查询、新增、编辑、任课维护 | 教师管理 |
| Student Course API | `/api/student-courses` | 学生课程分配、重复校验、停用 | 学生课程管理 |
| Score API | `/api/scores` | 成绩录入、编辑、查询 | 学生成绩管理 |

接口必须统一返回结构、错误码和分页结构。详细设计和编码阶段不得让各模块自行定义不一致的响应格式。

## 11. 安全与权限策略

| 策略编号 | 策略 | 说明 | 验证方式 |
|----------|------|------|----------|
| SEC-001 | 登录后访问 | 除登录接口外，所有业务接口必须校验登录态 | 接口测试未登录访问返回 `UNAUTHORIZED` |
| SEC-002 | 菜单权限 | 前端按角色显示菜单，后端仍要校验接口权限 | 切换角色验证菜单和接口 |
| SEC-003 | 数据权限 | 班主任只能访问本班数据，任课教师只能访问任教课程数据 | QA 覆盖越权查询和越权录入 |
| SEC-004 | 错误信息控制 | 不向用户暴露数据库异常和堆栈 | 异常测试返回业务错误码 |

## 12. 质量属性策略

| 质量属性 | 目标 | 架构策略 | 下游验证 |
|----------|------|----------|----------|
| 可维护性 | 模块边界清楚，便于 AI 和人工协作 | 按业务模块分包，统一 common 能力 | 代码评审检查分层和依赖 |
| 可测试性 | 关键业务规则可独立验证 | Service 层承载业务规则，接口返回统一 | 单元测试和接口测试覆盖 |
| 数据一致性 | 避免重复学生、重复课程关系、非法成绩 | 服务层校验 + 数据库约束 | 数据库脚本和测试用例覆盖 |
| 可部署性 | 本地一键启动 Demo | 提供 Docker Compose 或启动脚本 | 发布阶段执行启动验证 |
