# 页面原型说明 v1.0

项目：中学教务管理系统 Demo

阶段：原型设计与页面说明

## 1. 原型目标

通过页面清单、页面入口、字段、按钮说明和可运行前端原型，让业务负责人确认系统操作方式，并为详细设计阶段的软件功能说明文档提供页面、视觉和交互输入。

原型阶段不仅产出文档，也可以产出一个可运行的前端演示系统。本 Demo 的可运行原型位于：

```text
01_req/workspace/01_requirements/03_prototypes/prototype-app/
```

运行方式：

```bash
cd docs/demo/01_req/workspace/01_requirements/03_prototypes/prototype-app
npm start
```

默认访问地址：

```text
http://localhost:4173
```

## 2. 页面清单

| 页面编号 | 页面 | 关联需求 | 主要使用角色 |
|----------|------|----------|--------------|
| UI-001 | 登录页 | REQ-001 | 全部用户 |
| UI-002 | 主页 | REQ-002 | 全部用户 |
| UI-003 | 学生管理页 | REQ-003 | 教务管理员、班主任 |
| UI-004 | 班级管理页 | REQ-004 | 教务管理员 |
| UI-005 | 教师管理页 | REQ-005 | 教务管理员 |
| UI-006 | 学生课程管理页 | REQ-006 | 教务管理员、任课教师 |
| UI-007 | 学生成绩管理页 | REQ-007 | 教务管理员、班主任、任课教师 |

## 3. 页面流转

```text
登录页
  -> 主页
     -> 学生管理
     -> 班级管理
     -> 教师管理
     -> 学生课程管理
     -> 学生成绩管理
```

不同角色登录后看到的菜单不同：

- 教务管理员：可见全部教务模块。
- 班主任：可见学生管理、学生成绩管理，只能查看本班数据。
- 任课教师：可见学生课程管理、学生成绩管理，只能查看和维护任教课程相关数据。
- 系统管理员：可见账号和角色相关入口，本 Demo 不展开账号管理细节。

## 4. 示例页面字段

### 4.1 学生管理页

| 区域 | 字段或按钮 | 说明 |
|------|------------|------|
| 查询区 | 学号、姓名、班级、状态 | 支持组合查询 |
| 列表区 | 学号、姓名、性别、班级、状态 | 分页展示 |
| 操作区 | 新增、编辑、停用、查看 | 按角色和状态控制按钮 |
| 表单区 | 学号、姓名、性别、班级、入学年份、状态 | 新增和编辑共用 |

### 4.2 学生成绩管理页

| 区域 | 字段或按钮 | 说明 |
|------|------------|------|
| 查询区 | 学期、班级、课程、学生姓名 | 支持按班级和课程查询 |
| 列表区 | 学生、班级、课程、成绩、录入教师 | 展示成绩记录 |
| 操作区 | 录入、编辑、导入、查看 | 任课教师只能维护任教课程 |
| 表单区 | 学生、课程、成绩、备注 | 成绩范围 0-100 |

## 6. 可运行原型系统说明

| 产物 | 说明 |
|------|------|
| `prototype-app/package.json` | Node 启动脚本 |
| `prototype-app/server.mjs` | 本地静态服务 |
| `prototype-app/index.html` | 原型页面入口 |
| `prototype-app/src/main.js` | Vue 页面逻辑和模拟数据 |
| `prototype-app/src/styles.css` | 页面视觉样式 |

### 6.1 原型系统用途

- 业务人员用来确认页面是否符合操作习惯。
- 业务分析人员用来快速收集反馈并迭代页面。
- 详细设计人员用来补充页面字段、按钮、权限和异常场景。
- 开发人员用来理解页面结构、视觉布局和交互参考。

### 6.2 AI-Agent 与人工分工

| 工作 | 执行主体 | 说明 |
|------|----------|------|
| 根据需求生成页面结构和模拟数据 | AI-Agent | 形成可运行原型初稿 |
| 根据角色权限生成菜单和页面可见性 | AI-Agent | 帮助业务确认权限边界 |
| 确认页面字段、按钮和交互流程 | 人工 | 业务分析人员和业务负责人确认 |
| 记录反馈并决定是否采纳 | 人工 | 防止 AI 自行改变业务范围 |
| 根据反馈调整原型 | 业务分析人员主导，AI-Agent 辅助 | 调整后同步更新原型说明和需求基线 |

### 6.3 原型与后续开发关系

可运行原型提供视觉和交互参考，但不是正式生产代码。后续开发应以详细设计阶段输出的软件功能说明文档、接口契约、数据库设计和编码规则为准。

## 7. 下游交接

本文件交给详细设计阶段，用于生成各模块的软件功能说明文档。详细设计不得只引用页面名称，必须引用页面字段、按钮和交互规则。

交给详细设计阶段的产物包括：

- 页面原型说明。
- 可运行 Vue 原型系统。
- 页面字段和按钮说明。
- 业务反馈与人工确认结论。
