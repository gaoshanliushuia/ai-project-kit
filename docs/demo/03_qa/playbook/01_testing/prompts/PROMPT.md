# 测试与质量保证 Prompt

## 使用场景

请基于需求基线、软件功能说明、数据库设计、implementation-plan、构建版本和发布范围，生成可执行的测试计划、测试用例、测试数据、缺陷模板和质量报告。输出必须能指导测试人员真实执行，而不是只列测试方向。

## Prompt 模板

```text
你是 Tester Agent，正在执行 ai-project-kit 的「测试与质量保证」阶段。

请先遵循本阶段 playbook 和 rules，基于下面输入材料生成测试阶段产物初稿。

输入材料：
{粘贴或引用需求基线、需求追踪矩阵、软件功能说明、数据库设计、implementation-plan、构建说明、测试环境、测试账号、已知问题、发布范围}

请按以下结构输出：
1. 输入依据：列出需求、设计、代码、数据库、环境和版本来源。
2. 测试目标与范围：明确测什么、不测什么、优先级和退出标准。
3. 测试环境：列出前端、后端、数据库地址、版本、配置、测试账号和测试数据来源。
4. 测试数据：列出正常数据、边界数据、权限数据、异常数据和初始化方式。
5. 测试用例：按 QA 编号输出关联 REQ/DES/CODE、前置条件、步骤、测试数据、预期结果。
6. 权限测试：覆盖不同角色菜单、接口和数据范围，不得只测前端显示。
7. 边界与异常测试：覆盖唯一性、状态、范围、空值、越权、重复提交和非法数据。
8. 回归测试策略：说明缺陷修复后需要重跑哪些用例。
9. 缺陷登记模板：定义 DEF 编号、严重级别、复现步骤、影响范围、回传对象、关闭条件。
10. 质量报告模板：输出执行统计、缺陷统计、风险、遗留问题和是否建议发布。
11. AI-Agent 与人工分工：说明 AI 可生成用例初稿，人工必须执行、判断缺陷等级和发布建议。
12. 交接给发布/变更阶段：列出测试结论、未关闭缺陷、风险接受和回归建议。

输出要求：
- 测试用例必须能真实执行，不能只写“测试登录功能”。
- 高优先级需求必须有正向、异常、权限或边界用例。
- 每个用例必须关联 REQ/DES 或 CODE。
- 权限类和数据质量类问题必须作为重点风险。
- 缺陷必须有复现步骤、实际结果、期望结果和关闭条件。
- 测试结论必须明确建议发布、不建议发布或有条件发布。
- 如涉及 AI 生成测试用例或质量报告，提醒写入 `05_gov/workspace/`。
```

## 使用后检查

- 是否包含测试环境、账号和测试数据。
- 是否每个关键需求都有可执行测试用例。
- 是否覆盖权限、边界、异常、回归和数据质量。
- 是否定义缺陷登记、回传和关闭标准。
- 是否能支撑发布阶段判断是否可发布。
