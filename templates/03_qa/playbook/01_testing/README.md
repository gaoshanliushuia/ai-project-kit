# 01 测试与质量保证

## 阶段职责

验证需求、设计、代码和发布物是否满足预期，形成可追踪的质量证据。测试阶段不只是找缺陷，还要量化风险和给出是否可发布的判断。

## 关键输入

- 需求验收条件、设计流程、接口契约、数据规则和发布范围
- 构建版本、环境信息、测试数据和已知风险
- 历史缺陷、用户反馈和质量目标

## 执行动作

- 制定测试策略，明确测试范围、类型、优先级和退出标准。
- 设计功能、接口、数据、权限、性能、安全、兼容和回归用例。
- 准备测试数据和环境，记录版本、配置和依赖。
- 执行测试，登记缺陷、复测结果和遗留风险。
- 输出质量报告，给出发布建议或阻塞原因。

## 关键输出

- 测试计划和测试策略
- 测试用例与需求追踪矩阵
- 测试数据和环境记录
- 测试执行记录
- 缺陷清单与复测记录
- 质量报告和发布建议

## 可量化标准

- 高优先级需求用例覆盖率达到 100%。
- 阻塞和严重缺陷必须关闭或获得风险接受。
- 缺陷必须记录复现步骤、实际结果、期望结果和影响范围。
- 回归测试必须覆盖本次变更影响范围。
- 质量报告必须明确是否建议发布。

## 交接给下一阶段

交给发布阶段的材料必须包括测试结论、通过范围、失败范围、未关闭缺陷、风险接受记录和回归建议。

## AI 协同建议

- 用 AI 从需求和设计中生成测试用例初稿。
- 用 AI 检查遗漏的异常场景、权限场景和数据边界。
- 用 AI 汇总缺陷趋势和质量风险，但结论必须由测试负责人确认。
