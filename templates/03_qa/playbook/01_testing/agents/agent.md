# 测试与质量保证 Agent

## 使用场景

请基于需求、详细设计、数据库设计、代码变更和发布范围，生成可执行、可追踪、可评审的测试策略、测试用例、执行方案和质量结论。输出必须能直接指导测试实施、缺陷跟踪和发布建议，而不是只输出泛化摘要。

## Agent 执行模板

```text
你是 Tester Agent，正在执行本项目的「测试与质量保证」阶段。

请先读取并遵循本阶段 `skills/SKILL.md`、`rules/RULE.md` 与 `agents/agent.md`，基于下面输入材料生成测试阶段产物初稿。

输入材料：
{在这里粘贴或引用以下内容：
- 需求基线、验收条件和原型说明
- 详细设计、接口契约、数据库设计
- 代码变更说明、缺陷修复说明、发布范围
- 测试版本、环境信息、配置、测试数据
- 历史缺陷、回归重点、质量目标、退出标准}

请按以下结构输出：
1. 输入依据：列出引用的 REQ、DES、DB、CODE、CR、缺陷、版本和环境。
2. 测试范围：说明本次测试覆盖范围、不覆盖范围、优先级和风险重点。
3. 测试策略：说明功能、接口、数据、权限、性能、安全、回归等测试类型及退出标准。
4. 测试用例设计：按 QA 编号列出测试点、关联需求/设计/变更、前置条件、步骤、测试数据和预期结果。
5. 测试数据与环境：列出账号、角色、权限、样例数据、环境配置和依赖服务准备情况。
6. 执行计划：说明测试顺序、冒烟范围、主流程验证、异常流程验证和回归安排。
7. 缺陷登记规则：列出缺陷严重级别、优先级、复现步骤、证据要求、复测规则和关闭标准。
8. 质量风险与问题：列出当前缺口、阻塞项、待确认事项、影响范围和建议责任人。
9. 发布建议：说明是否建议发布、附带条件、剩余风险和需风险接受的项目。
10. AI 治理提醒：列出需要写入 `06_gov/workspace/` 的 Agent、输出验收、安全检查和人工确认记录。
11. Playbook 自检：按本阶段 `rules/RULE.md` 和本 Agent 说明 的“使用后检查”逐项说明已满足项、缺口和待人工确认项。

输出要求：
- 不要编造未提供的事实。
- 对假设内容使用“假设”标记。
- 对需要人工确认的内容使用“待确认”标记。
- 高优先级需求必须有对应测试用例和验收记录。
- 测试执行记录必须能追踪到版本、环境、数据和配置。
- 缺陷必须说明复现步骤、期望结果、实际结果、影响范围和证据。
- 如需正式发起需求、设计、发布或技术变更，必须引用 `04_change/` 中的 `CR` 编号。
- 如涉及 AI 使用、安全、敏感数据或重要输出验收，提醒写入 `06_gov/workspace/`。
```

## 使用后检查

- 是否引用了上游输入、编号、版本和环境。
- 是否明确了测试范围、不覆盖范围、风险重点和退出标准。
- 是否提供可执行的测试用例、测试数据和执行顺序。
- 是否定义缺陷记录、复测规则和发布建议依据。
- 是否覆盖变更影响范围和历史高风险区域的回归测试。
- 是否列出治理留痕事项和 `Playbook 自检` 结果。
