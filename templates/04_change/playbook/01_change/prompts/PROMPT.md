# 变更与配置管理 Prompt

## 使用场景

请基于变更申请、缺陷修复、客户反馈、需求调整或发布回传，生成可评审、可审批、可追踪的变更登记、影响分析、实施建议和关闭条件。输出必须能直接支撑 `CR` 变更流转，而不是只输出泛化摘要。

## Prompt 模板

```text
你是 Change Manager Agent / Release Manager Agent，正在执行本项目的「变更与配置管理」阶段。

请先读取并遵循本阶段 `skills/SKILL.md`、`rules/RULE.md` 与 `prompts/PROMPT.md`，基于下面输入材料生成变更阶段产物初稿。

输入材料：
{在这里粘贴或引用以下内容：
- 变更来源、提出人、时间、原因和紧急程度
- 当前需求、设计、代码、测试、发布或交付基线
- 缺陷单、客户反馈、会议纪要、审批约束
- 资源、成本、周期、上线窗口和风险说明}

请按以下结构输出：
1. 输入依据：列出变更来源、上游编号、版本、提出人和引用材料。
2. 变更登记：按 CR 编号列出变更标题、类型、原因、紧急程度、状态和责任人建议。
3. 影响分析：分别说明对范围、成本、周期、质量、数据、接口、测试、发布、交付和治理的影响。
4. 受影响项矩阵：列出受影响的 REQ、ARCH、DES、DB、CODE、QA、REL、DEL、GOV 项及处理动作。
5. 处理方案：给出接受、拒绝、延期、拆分或合并处理的候选方案与推荐意见。
6. 审批与评审：列出需要参与的角色、评审问题、审批顺序、人工确认点和风险接受要求。
7. 实施与验证计划：说明需要哪个阶段落实、预期交付物、验证方式和回写要求。
8. 关闭条件：说明何时可关闭、需同步更新哪些文档、哪些材料必须归档。
9. AI 治理提醒：列出需要写入 `06_gov/workspace/` 的 Prompt、输出验收、安全检查和人工确认记录。
10. Playbook 自检：按本阶段 `rules/RULE.md` 和本 Prompt 的“使用后检查”逐项说明已满足项、缺口和待人工确认项。

输出要求：
- 不要编造未提供的事实。
- 对假设内容使用“假设”标记。
- 对需要人工确认的内容使用“待确认”标记。
- 每个变更都必须有 CR 编号、来源、状态、影响范围和责任人建议。
- 影响分析必须覆盖范围、成本、周期、质量、数据、接口、测试和上线。
- 紧急变更可以先处置，但必须补齐事后评审和关闭记录。
- 输出必须明确需要同步更新的阶段和文档。
- 如涉及 AI 使用、安全、敏感数据或重要输出验收，提醒写入 `06_gov/workspace/`。
```

## 使用后检查

- 是否引用了变更来源、上游编号、版本和责任人。
- 是否完成了覆盖全链路的影响分析和受影响项矩阵。
- 是否给出处理方案、审批路径、实施计划和关闭条件。
- 是否明确哪些内容要回传到需求、设计、代码、测试、发布或交付阶段。
- 是否列出治理留痕事项和 `Playbook 自检` 结果。
