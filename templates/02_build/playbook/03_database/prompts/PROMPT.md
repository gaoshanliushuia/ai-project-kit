# 数据库设计 Prompt

## 使用场景

请基于软件功能说明、接口字段、业务对象、状态规则和数据质量要求，生成可执行、可评审、可交接给编码和测试阶段的数据库设计。输出必须包含数据定义、约束、索引、脚本和初始化数据要求。

## Prompt 模板

```text
你是 DBA Agent，正在执行本项目的「数据库设计」阶段。

请先读取并遵循本阶段 `skills/SKILL.md`、`rules/RULE.md` 与 `prompts/PROMPT.md`，基于下面输入材料生成 `database-design` 初稿。

输入材料：
{粘贴或引用软件功能说明、架构设计、需求基线、接口契约、页面字段、业务规则、数据安全要求、现有数据结构、数据库技术栈}

请按以下结构输出：
1. 输入依据：列出需求、设计、接口、业务对象和数据库技术栈来源。
2. 数据模型总览：列出核心实体、表名、DB 编号、说明、关联 REQ/DES。
3. 实体关系：说明一对一、一对多、多对多关系和业务含义。
4. 字段字典：每张表列出字段名、类型、长度、必填、默认值、主键、外键、唯一性、枚举、说明。
5. 约束设计：列出主键、唯一约束、非空约束、检查约束、外键或服务层约束。
6. 索引设计：列出索引名、字段、目的、查询场景和维护成本。
7. 数据质量规则：列出唯一性、状态、范围、跨表校验、历史数据和审计要求。
8. DDL 脚本：输出可执行建表、索引和约束脚本；若只是片段必须说明如何落成脚本。
9. 初始化数据：列出角色、菜单、字典、演示账号、基础业务数据。
10. 迁移与回滚：说明脚本执行顺序、回滚或重建方式、失败处理。
11. 测试数据建议：提供测试阶段可用的边界值和权限验证数据。
12. AI-Agent 与人工分工：说明哪些可由 AI 初稿生成，哪些必须 DBA 或负责人确认。
13. 数据库评审清单：列出进入编码前必须确认的检查项。
14. 下游交接：明确交给编码、测试和发布阶段的脚本、字段字典和约束规则。

输出要求：
- 不要凭空发明业务字段；不确定字段标记“待确认”。
- 字段定义必须可落地到数据库脚本。
- 每个业务唯一性规则必须说明数据库约束或 Service 层校验位置。
- 关键查询必须有索引建议。
- 初始化数据和测试数据必须与需求、设计、测试场景一致。
- 数据库脚本必须有执行顺序和回滚或重建说明。
- 涉及敏感字段、权限或生产数据时必须提醒脱敏和治理留痕。
```

## 使用后检查

- 是否覆盖软件功能说明中的所有数据对象。
- 是否有字段字典、约束、索引、DDL、初始化数据和回滚说明。
- 是否明确哪些规则由数据库实现，哪些由 Service 层实现。
- 是否能支撑 AI-Agent 生成 Entity、Repository、DTO 和数据库脚本。
- 是否能支撑测试数据准备和发布脚本执行。
