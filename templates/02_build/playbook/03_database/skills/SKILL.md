# 数据库设计 Skill

## 目标

把业务对象、状态规则、查询需求和集成数据转化为稳定的数据模型和迁移方案。

## 适用角色

- `DBA Agent`

## 输入

数据需求、接口字段、领域对象、状态规则、历史数据、报表和审计要求。

## 输出

数据模型、字段字典、索引与约束、迁移脚本计划、数据质量规则、回滚说明。

## 标准执行顺序

1. 先读取本阶段 `skills/SKILL.md`，确认目标、输入输出和执行边界。
2. 再读取本阶段 `rules/RULE.md`，检查进入条件、目录结构、编号规则和退出要求。
3. 再读取本阶段 `prompts/PROMPT.md`，按标准输出结构组织数据库设计产物。
4. 若输入材料不完整，先列出缺口、假设、待确认事项和影响范围，不得直接编造业务字段、索引或脚本约束。
5. 生成或检查阶段产物时，必须引用需求编号、设计编号、版本和评审记录。
6. 输出前必须按 `rules/RULE.md` 与 `prompts/PROMPT.md` 的“使用后检查”完成自检。
7. 若发现本阶段 playbook 存在冲突、过时或缺漏，先在结果中指出，再回写修正 `rules/`、`skills/` 或 `prompts/`。

## 执行步骤

- 识别核心实体、关系、生命周期和数据所有者。
- 定义表、字段、类型、约束、索引、字典和审计字段。
- 标注敏感字段、访问控制、脱敏和审计要求。
- 设计初始化、迁移、校验和回滚策略。
- 输出容量、性能和数据质量风险。

## 使用要求

- 本阶段执行入口默认是：`skills/SKILL.md` -> `rules/RULE.md` -> `prompts/PROMPT.md`。
- 生成阶段产物前，必须先确认输入完整性、编号前缀、引用版本、人工确认点和下游交接对象。
- 所有结论必须能追踪到输入材料、编号、负责人或评审记录。
- AI 生成内容只作为初稿或检查建议，关键结论必须由阶段负责人确认。
- 输出前必须完成一次 playbook 自检，至少覆盖进入条件、编号追踪、产物结构、AI 治理留痕和交接要求。
- 发现可复用经验时，回写本阶段 `rules/`、`skills/` 或 `prompts/`，并在后续版本发布中说明。
