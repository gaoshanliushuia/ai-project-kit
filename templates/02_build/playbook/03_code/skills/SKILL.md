# 代码实现与工程管理 Skill

## 目标

把设计项转化为可构建、可测试、可审查、可发布的代码实现。

## 适用角色

- `Developer Agent`

## 输入

需求编号、设计项、接口契约、数据模型、代码规范、分支策略、测试要求。

## 输出

开发任务、实现计划、测试记录、构建记录、代码评审问题、缺陷修复记录。

## 标准执行顺序

1. 激活本阶段 `skills/SKILL.md` 作为执行入口，确认目标、输入输出和执行边界。
2. 再读取本阶段 `rules/RULE.md`，检查进入条件、代码阶段约束、验证要求和退出要求。
3. 读取本阶段 `agents/agent.md`；该 Agent 同时覆盖任务拆分、实现检查、阶段交接和可运行代码生成。
4. 若要生成可运行代码，必须基于已确认的需求、设计、数据库和编码规则，按 `agents/agent.md` 的模块化代码生成流程逐模块生成。
5. 若输入材料不完整，先列出缺口、假设、待确认事项和影响范围，不得直接编造业务实现细节。
6. 生成或检查阶段产物时，必须引用需求编号、设计编号、数据库编号、代码任务编号、版本和评审记录。
7. 若任务涉及专项能力且符合「第三方 Skill 协作（预留）」中的触发条件，可先引用对应第三方 Skill；完成后必须回到本阶段流程继续执行，并在结果中记录第三方 Skill 使用留痕。
8. 输出前必须按 `rules/RULE.md` 与对应 Agent 的“使用后检查”完成自检。
9. 若发现本阶段 playbook 存在冲突、过时或缺漏，先在结果中指出，再回写修正 `rules/`、`skills/` 或 `agents/`。

## 执行步骤

- 把设计项拆成可追踪的开发任务。
- 确认影响范围、依赖、配置项和验证方式。
- 实现代码并补齐关键路径测试或人工验证证据。
- 记录代码评审问题、修复结论和遗留风险。
- 整理交给测试和发布的变更说明。

## 第三方 Skill 协作（预留）

本阶段 Skill 负责主流程编排。若任务涉及专项能力，可引用本地第三方 Skill 协助，但第三方 Skill 不得替代本阶段流程。

### 协作原则

- 先激活本阶段 Skill，再判断是否需引用第三方 Skill。
- 第三方 Skill 只处理专项任务，完成后必须回到本阶段 `rules/RULE.md` 与 `agents/agent.md` 继续执行。
- 未在本节明确登记、且未经人工确认的第三方 Skill，不得擅自启用。
- 第三方 Skill 的输出只能作为建议或初稿，关键结论仍须按本阶段 rule 与人工确认要求处理。

## 使用要求

- 本阶段执行入口默认是：激活 `skills/SKILL.md`，再遵循 `rules/RULE.md`、`agents/agent.md`；`agents/agent.md` 是本阶段唯一 Agent 入口。
- 生成阶段产物前，必须先确认输入完整性、编号前缀、引用版本、人工确认点和下游交接对象。
- 所有结论必须能追踪到输入材料、编号、负责人或评审记录。
- AI 生成内容只作为初稿或检查建议，关键结论必须由阶段负责人确认。
- 输出前必须完成一次 playbook 自检，至少覆盖进入条件、编号追踪、产物结构、AI 治理留痕和交接要求。
- 发现可复用经验时，回写本阶段 `rules/`、`skills/` 或 `agents/`，并在后续版本发布中说明。
- 若引用了第三方 Skill，是否记录使用留痕并回到本阶段主流程继续执行。
