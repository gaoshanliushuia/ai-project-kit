# 03 代码实现与工程管理

## 阶段职责

把详细设计阶段产出的模块级开发实现文档转化为可构建、可测试、可审查、可发布的代码实现。代码阶段关注源码、工程质量、任务闭环、缺陷处理和构建证据，不保存实现计划文档。

## 关键输入

- 需求编号、设计项、接口契约、数据模型、模块级开发实现文档和测试关注点
- 技术栈、代码规范、分支策略、依赖管理和安全要求
- 发布计划、环境约束和第三方集成资料

## 执行动作

- 根据 `02_build/workspace/02_design/common/` 下的公共设计文件，以及 `02_build/workspace/02_design/modules/` 下的模块级设计与实现文档生成代码。
- 按模块级实现文档执行开发任务，并建立代码变更与需求/设计的映射。
- 编写业务代码、接口代码、数据访问、配置和自动化脚本。
- 完成单元测试、静态检查、依赖检查和本地构建。
- 进行代码评审，记录问题、修复和复审结论。
- 维护缺陷、技术债、临时方案和遗留风险。
- 固化构建方式、环境变量、配置项和部署依赖。

## 关键输出

- 源码、脚本、配置和运行说明
- 代码提交、构建记录和测试记录
- 代码评审记录
- 缺陷修复记录
- 配置说明和运行说明
- 技术债与遗留风险清单

## 可量化标准

- 代码变更必须能追踪到需求、设计项和模块级实现文档。
- 关键路径代码必须有测试或人工验证证据。
- 代码评审问题关闭后才能合并。
- 构建失败、静态检查失败和阻塞缺陷必须有处理结论。
- 临时方案必须记录失效条件和后续处理计划。

## 交接给下一阶段

交给测试和发布阶段的材料必须包括版本分支、构建方式、配置项、已知问题、变更点、测试入口和回滚注意事项。公共设计文件应继续引用 `02_build/workspace/02_design/common/`，模块级实现说明继续引用 `02_build/workspace/02_design/modules/`，不复制到代码阶段工作区。

## AI 协同建议

- 用 AI 根据模块级实现文档生成代码骨架和模块实现。
- 用 AI 辅助检查边界条件、异常处理和测试遗漏。
- 用 AI 生成代码评审问题清单，但不能替代人工评审。

## Prompt 使用

本阶段唯一 Prompt 入口放在 `prompts/PROMPT.md`。它同时覆盖代码阶段任务拆分、验证交接和可运行代码生成；生成代码时负责读取 `02_build/workspace/02_design/common/` 下的公共设计文件，以及 `02_build/workspace/02_design/modules/` 下的单个模块级设计与实现文档，并生成实际代码、脚本、测试和运行说明。
