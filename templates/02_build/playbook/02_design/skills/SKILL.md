# 详细设计 Skill

## 目标

把架构方案细化为开发可执行、测试可验证、变更可分析的设计产物。

## 适用角色

- `Architect Agent / Developer Agent`

## 输入

需求编号、验收条件、架构决策、模块边界、接口约束、数据和权限规则。

## 输出

模块设计、接口契约、流程图、状态机、异常处理、设计追踪矩阵。

## 标准执行顺序

1. 先读取本阶段 `skills/SKILL.md`，确认目标、输入输出和执行边界。
2. 再读取本阶段 `rules/RULE.md`，检查进入条件、目录结构、编号规则和退出要求。
3. 再读取本阶段 `prompts/PROMPT.md`，用于生成统一的详细设计文档集。
4. 该详细设计文档集必须同时承载业务设计说明与实现指导内容，不再额外拆分独立的实现计划 Prompt。
5. 若输入材料不完整，先列出缺口、假设、待确认事项和影响范围，不得直接编造业务规则或接口契约。
6. 生成或检查阶段产物时，必须引用需求编号、架构决策、模块编号、版本和评审记录。
7. 输出前必须按 `rules/RULE.md` 与 `prompts/PROMPT.md` 的“使用后检查”完成自检。
8. 若发现本阶段 playbook 存在冲突、过时或缺漏，先在结果中指出，再回写修正 `rules/`、`skills/` 或 `prompts/`。

## 执行步骤

- 明确模块职责、输入输出、依赖关系和边界条件。
- 设计接口字段、类型、校验、鉴权、错误码、超时、重试和幂等。
- 补齐主流程、异常流程、补偿流程和并发场景。
- 定义状态流转、禁止条件和终态。
- 提取开发任务和测试关注点。

## 使用要求

- 本阶段执行入口默认是：`skills/SKILL.md` -> `rules/RULE.md` -> `prompts/PROMPT.md`。
- 生成阶段产物前，必须先确认输入完整性、编号前缀、引用版本、人工确认点和下游交接对象。
- 所有结论必须能追踪到输入材料、编号、负责人或评审记录。
- AI 生成内容只作为初稿或检查建议，关键结论必须由阶段负责人确认。
- 统一设计文档集必须同时覆盖业务功能、接口契约、流程状态、数据约束、实现指导、测试关注点和 AI 代码生成约束。
- 输出前必须完成一次 playbook 自检，至少覆盖进入条件、编号追踪、产物结构、AI 治理留痕和交接要求。
- 发现可复用经验时，回写本阶段 `rules/`、`skills/` 或 `prompts/`，并在后续版本发布中说明。
