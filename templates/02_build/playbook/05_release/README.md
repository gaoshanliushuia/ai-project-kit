# 05 版本发布与迭代

## 阶段职责

把通过验证的代码、配置、脚本和说明组织成可发布、可回滚、可复盘的版本。发布阶段关注版本边界、环境准备、发布验证和问题回收。

## 关键输入

- 发布范围、版本计划、代码分支、构建产物和配置项
- 数据库脚本、初始化数据、部署脚本和环境资源
- 测试结论、未关闭缺陷、风险接受记录和上线窗口

## 执行动作

- 明确版本号、发布范围、包含需求、排除项和已知问题。
- 准备构建产物、脚本、配置、部署说明和回滚方案。
- 完成发布前检查，包括环境、权限、依赖、容量和备份。
- 执行发布验证，记录结果、异常、处理人和关闭情况。
- 发布后收集问题、用户反馈和改进项，进入下一轮迭代。

## 关键输出

- 发布计划和发布清单
- 构建产物记录
- 部署说明和回滚说明
- 发布验证记录
- 已知问题与风险接受记录
- 版本复盘和下一轮迭代建议

## 可量化标准

- 每个发布项都能关联到需求、变更或缺陷。
- 发布前检查项完成率达到 100%。
- 回滚步骤必须可执行，并明确触发条件。
- 发布验证通过率达到项目约定阈值。
- 发布问题必须进入缺陷、变更或复盘清单。

## 交接给下一阶段

交给交付阶段的材料必须包括最终版本号、部署记录、验证结论、账号权限、运维注意事项、已知问题和验收范围。

## AI 协同建议

- 用 AI 汇总发布说明、变更点和风险清单。
- 用 AI 根据历史发布问题生成发布前检查项。
- 用 AI 辅助生成回滚演练和验证场景。
