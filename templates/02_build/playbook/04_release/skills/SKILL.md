# 版本发布与迭代 Skill

## 目标

把通过验证的代码、配置、脚本和说明组织成可发布、可回滚、可复盘的版本。

## 适用角色

- `Release Manager Agent`

## 输入

发布范围、版本号、构建产物、配置项、测试结论、风险接受、上线窗口。

## 输出

发布计划、发布清单、部署说明、回滚说明、发布验证记录、版本复盘。

## 标准执行顺序

1. 激活本阶段 `skills/SKILL.md` 作为执行入口，确认目标、输入输出和执行边界。
2. 再读取本阶段 `rules/RULE.md`，检查进入条件、发布检查项、回滚要求和退出要求。
3. 再读取本阶段 `agents/agent.md`，按标准输出结构组织发布计划和发布说明。
4. 若输入材料不完整，先列出缺口、假设、待确认事项和影响范围，不得直接编造环境、账号、脚本或风险接受事实。
5. 生成或检查阶段产物时，必须引用版本号、构建记录、测试结论、变更编号和评审记录。
6. 若任务涉及专项能力且符合「第三方 Skill 协作（预留）」中的触发条件，可先引用对应第三方 Skill；完成后必须回到本阶段流程继续执行，并在结果中记录第三方 Skill 使用留痕。
7. 输出前必须按 `rules/RULE.md` 与 `agents/agent.md` 的“使用后检查”完成自检。
8. 若发现本阶段 playbook 存在冲突、过时或缺漏，先在结果中指出，再回写修正 `rules/`、`skills/` 或 `agents/`。

## 执行步骤

- 确认版本范围、包含项、排除项和已知问题。
- 准备构建产物、脚本、配置、部署步骤和回滚步骤。
- 完成环境、权限、依赖、容量和备份检查。
- 记录发布验证结果、异常处理和关闭状态。
- 汇总发布问题和下一轮迭代建议。

## 第三方 Skill 协作（预留）

本阶段 Skill 负责主流程编排。若任务涉及专项能力，可引用本地第三方 Skill 协助，但第三方 Skill 不得替代本阶段流程。

### 协作原则

- 先激活本阶段 Skill，再判断是否需引用第三方 Skill。
- 第三方 Skill 只处理专项任务，完成后必须回到本阶段 `rules/RULE.md` 与 `agents/agent.md` 继续执行。
- 未在本节明确登记、且未经人工确认的第三方 Skill，不得擅自启用。
- 第三方 Skill 的输出只能作为建议或初稿，关键结论仍须按本阶段 rule 与人工确认要求处理。

### 引用后必须记录

## 使用要求

- 本阶段执行入口默认是：激活 `skills/SKILL.md`，再遵循 `rules/RULE.md` 与 `agents/agent.md`。
- 生成阶段产物前，必须先确认输入完整性、编号前缀、引用版本、人工确认点和下游交接对象。
- 所有结论必须能追踪到输入材料、编号、负责人或评审记录。
- AI 生成内容只作为初稿或检查建议，关键结论必须由阶段负责人确认。
- 输出前必须完成一次 playbook 自检，至少覆盖进入条件、编号追踪、产物结构、AI 治理留痕和交接要求。
- 发现可复用经验时，回写本阶段 `rules/`、`skills/` 或 `agents/`，并在后续版本发布中说明。
- 若引用了第三方 Skill，是否记录使用留痕并回到本阶段主流程继续执行。
