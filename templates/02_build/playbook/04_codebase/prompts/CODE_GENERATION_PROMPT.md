# 可运行代码生成 Prompt

## 使用场景

当 `implementation-plan` 已经完成并通过人工审查后，使用本 Prompt 指导 AI-Agent 生成可运行的前端代码、后端代码、数据库脚本、测试和本地部署脚本。

本 Prompt 不用于重新发散需求，也不用于重新设计架构。AI-Agent 必须严格依据已确认的需求基线、架构设计、软件功能说明、数据库设计和 `implementation-plan` 生成代码。

## Prompt 模板

```text
你是 Developer Agent，正在执行 ai-project-kit 的「代码实现与工程管理」阶段，现在要根据已确认的 implementation-plan 生成可运行代码。

请先读取并遵循以下材料：
1. 需求基线：{路径}
2. 架构设计：{路径}
3. 软件功能说明：{路径}
4. 数据库设计：{路径}
5. implementation-plan：{路径}
6. 编码规则：{路径}

生成目标：
- 可运行前端。
- 可运行后端。
- 数据库 schema 和 seed 脚本。
- 本地运行和部署脚本。
- 基础测试。
- README 和运行说明。

请按以下顺序工作：
1. 先生成项目骨架，不要一次性实现所有业务。
2. 生成数据库脚本和初始化数据。
3. 生成后端 common 能力：统一响应、错误码、异常处理、权限上下文、分页结构。
4. 按 CODE 编号逐个生成业务模块，每次只生成一个模块。
5. 每个模块必须读取 implementation-plan 中对应 CODE 章节，不得只按模块名发挥。
6. 每个模块必须包含前端页面、API 封装、后端 Controller、Service、Repository、Entity、DTO 和必要测试。
7. 生成部署脚本和本地启动说明。
8. 生成后必须说明如何运行、如何测试、如何验证核心业务。

每个 CODE 模块输出要求：
- 关联 REQ、DES、DB、CODE 编号。
- 前端页面和路由。
- 前端表单字段、表格字段、按钮和校验。
- 后端接口路径、方法、请求 DTO、响应 DTO。
- Entity、Repository、Service、Controller。
- 数据约束、唯一性规则、状态规则、范围规则。
- 权限过滤和越权处理。
- 异常和错误码。
- 测试用例或验证脚本。
- 人工审查点。

强制约束：
- 不得编造 implementation-plan 中没有的业务范围。
- 不得跳过后端校验，只做前端校验。
- 不得硬编码敏感信息；配置必须进入 env.example 或配置文件。
- 不得一次性生成不可审查的大块系统。
- 每次生成后必须列出新增文件、运行命令、测试命令和人工检查项。
- 如发现输入材料缺失，必须先列出缺口，不得自行补业务事实。
```

## 使用后检查

- 是否严格引用了已确认的上游产物。
- 是否按 CODE 模块逐步生成，而不是一次性生成全部。
- 是否生成可运行前端、后端、数据库脚本和部署脚本。
- 是否有测试或验证命令。
- 是否明确人工审查点。
- 是否避免硬编码敏感信息和未确认业务规则。
