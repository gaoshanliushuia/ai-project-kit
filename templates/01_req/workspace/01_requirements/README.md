# 01 需求收集与需求分析

## 本阶段目录用途

用于保存本项目的需求来源、需求分析过程、原型确认、评审结论和需求基线。这里的材料应能直接支撑架构设计、测试用例和最终验收。

## 建议目录

```text
01_stakeholders/       干系人、角色、业务负责人和确认人
02_research-notes/     访谈纪要、调研记录、现场观察和原始资料
03_scope/              范围内、范围外、假设、依赖和待确认事项
04_processes/          业务流程、异常流程、跨系统流程
05_requirements/       需求清单、用户故事、非功能需求和验收条件
06_prototypes/         原型、页面流转、交互说明和评审反馈
07_baseline/           已确认需求基线、版本记录和签审材料
08_traceability/       需求追踪矩阵和上下游引用关系
09_reviews/            评审纪要、问题清单和关闭记录
```

## 推荐文件

- `05_requirements/requirements-list.md`
- `05_requirements/non-functional-requirements.md`
- `03_scope/in-scope-out-of-scope.md`
- `08_traceability/requirements-traceability-matrix.md`
- `07_baseline/requirements-baseline-v<版本号>.md`

## 阶段完成标志

- 需求项已编号，并有来源、优先级、负责人和验收条件。
- 范围外事项和待确认事项已单独列出。
- 需求评审问题已关闭或形成明确遗留项。
- 需求基线可以被架构、设计、测试和验收阶段引用。
